# Demo Readiness Checklist

Use this checklist before presenting the repository in a technical interview.

## Before The Demo

- Open `README.md`, `docs/reviewer-entrypoint.md`, and `docs/technical-scope.md`.
- Be ready to explain why subscription lifecycle comes before payment integration.
- Prepare one example of an invalid subscription request and expected error.

## During The Demo

- Start with the domain boundary: subscription, billing, and payment.
- Show the next demo slice and acceptance criteria.
- Explain how tests and idempotency reduce billing risk.

## Strong Closing Point

This project is strongest when presented as a careful backend architecture plan
for money-related workflows, with a clear path toward executable behavior.
