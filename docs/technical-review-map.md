# Technical Review Map

Use this map to review the repository quickly without losing the technical story.

## Review Path

1. Start with `docs/technical-elevator-pitch.md` for the short positioning.
2. Read `docs/technical-scope.md` to understand what the project proves today.
3. Open `docs/architecture.md` for domain boundaries and system direction.
4. Check `docs/technical-risks.md` for failure modes and mitigations.
5. Finish with `docs/acceptance-criteria.md` to see what would make the next
   implementation slice review-ready.

## Reviewer Takeaway

The project should be evaluated as a backend architecture and API-design case
study for subscription billing, with emphasis on state, risk, tests, and
provider isolation.
