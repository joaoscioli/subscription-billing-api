# Demo Evaluation Rubric

Use this rubric to evaluate a technical walkthrough of this project.

| Area | Strong Signal | Weak Signal |
| --- | --- | --- |
| Domain modeling | Explains subscription lifecycle rules and boundaries. | Describes only CRUD endpoints. |
| API design | Shows validation, errors, and contract stability. | Focuses only on happy-path requests. |
| Architecture | Defends modular monolith and future integration points. | Jumps to microservices without a clear reason. |
| Production thinking | Names security, observability, billing, and audit gaps. | Claims production readiness without evidence. |

## Passing Bar

A strong demo connects technical choices to revenue protection, operational
clarity, and future payment-provider integration.
